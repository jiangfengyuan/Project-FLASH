## Threat model and preliminary implementation order

| Asset / boundary | Attacker and scenario | Existing controls / remaining questions |
| --- | --- | --- |
| Logs, ideas, emotions, tasks and backups | LAN host connects to an explicitly opened sender; passive observer captures raw backup; MITM injects a service, name or traffic | Current sender releases raw JSON after a public CHALLENGE. Receiver proof/MAC checks do not authenticate receiver or encrypt contents. **High priority**, all platforms; replacement requires approval |
| Pairing PIN and session material | Observer or rogue advertiser obtains nonce/proof and tests six-digit candidates offline; malicious client ignores backoff | HMAC directly keyed by PIN; no strong session key, transcript-bound AEAD or mutual confirmation. Client-only 5-attempt/backoff does not prevent this. Random challenge prevents verbatim proof replay under a new nonce, but payload MAC is not bound to nonce/role/version |
| LAN metadata and availability | Rogue advertisers spoof names/endpoints or flood listeners/partial frames; stalled socket monopolizes the session | One active sender connection, line/payload caps and timers exist. macOS advertises user host name; Android model. Minimize labels without changing wire format. Verify hard deadlines during blocked reads/writes, discovery cancellation and late callbacks |
| Imported data and existing database | Supplier provides malformed/oversized/nested/duplicate/unknown input, then cancellation or write failure occurs | Strict v2 and explicit recovery paths; 50MiB, 100k entries/section, text/date/time-zone checks, duplicate-key scanners. SwiftData/Room/RDB transactions and overwrite TOCTOU checks exist. Audit cancellation at commit, nesting/resource allocation, file races and failure rollback; preserve fixtures |
| Local stores, drafts, read-state, exports | Other apps/users, accidental OS cloud/device backup, share recipient, abandoned plaintext cache | Sandboxes/platform encryption and atomic writes; Android backup exclusions. Validate actual save/relaunch and read-state persistence, export permissions/cleanup, Apple/Harmony backup policy. Do not add a secret or migrate stores |
| Widget snapshots, lock-screen counts/mood, reminders | Nearby observer sees private summaries/titles | Apple snapshot contains counts/mood/unread count rather than bodies. Widget privacy sensitivity and notification-preview behavior need native verification; preserve refresh reliability and quick-capture actions |
| Deep links, App Intents and build chain | Untrusted app supplies capture/routing fields; source reader finds credentials; altered artifact/dependency reaches build | Trace allowed routes/parameters and bounds; inspect current source/config/tests without using secrets. No assumption that Bonjour names, URL schemes or fixture paths provide authentication |

Initial order: (1) preserve baseline and test counts; (2) compatible LAN resource/lifecycle and identity fixes, backup cancellation/resource fixes with failing-parent regressions; (3) local privacy/input/build-chain fixes with scoped tests; (4) optimize only measured bottlenecks; (5) UI preparation in independent documentation commits. Protocol confidentiality/mutual authentication is **not fixed** by compatible maintenance or a longer PIN.

## Release measurement plan

Use deterministic fictional data, fixed seed and reference date, same files/seed on before/after commits; retain manifest/hash and resulting counts. Do not seed or overwrite daily-use app containers.

| Dataset | Logs (includes ideas) | Emotions | Tasks | Time span / purpose |
| --- | ---: | ---: | ---: | --- |
| Small | 1,000 | 500 | 200 | 1 year, fresh/normal use |
| Medium | 10,000 | 5,000 | 2,000 | 5 years, substantial use |
| Large | 100,000 | 50,000 | 20,000 | 10 years, long-term high-frequency use; respects per-section count cap; keep serialized backup <=50MiB |

Mix Chinese/Latin/emoji, short/long bodies, rare/common/no-match search, same-day clusters, tags/favorites, completed/overdue/future tasks and time zones. Benchmark backup schema1 interoperability separately from Apple schema2; do not modify schema to make a benchmark pass. Existing DEBUG-only 10k microbenchmarks and historical README timings are **not** this pass's Release results. Existing debug seeder is not permission to enable synthetic data in a release app.

- Native tools: Apple Instruments/xctrace Time Profiler, Allocations, SwiftUI/Hitches and Points of Interest; Android Studio/Perfetto/system tracing + profiler; DevEco Profiler/SmartPerf. Host domain/parser timings must be labeled host microbenchmarks, never attributed to mobile hardware.
- Serial execution: one build/test/simulator/profiler at a time on the owner-reserved machine. Record competing processes, AC/battery/thermal state and simulator/emulator state. Stop unrelated build daemons before timing; don't kill another user's work. Separate build/seed/warm-up from timing. If idle conditions cannot be established, label exploratory and remeasure.
- For each metric: 2 warm-ups, at least7 timed samples (5 launches where repeated cold launches are costly); median and min/max plus all raw samples. Alternate baseline/candidate measurement order when practical. Record commit + dirty tree digest, platform/model/OS, toolchain, Release optimization/configuration, dataset counts/hash/bytes, locale/time zone, cache state and test conditions.
- Cold launch: process stopped to first usable frame; define cache state, never call process-detection time first-frame latency. Warm launch/resume separately. Scroll top/middle/end in records/log flow; record frame-time percentiles, missed-frame rate and RSS/peak memory.
- Search/filter/batch/global search: common/rare/absent term latency and stale-result/cancellation behavior. Calendar/emotion/review/Memory: week/month navigation and large chart rendering, same data/date on both commits.
- Database: fetch/query counts, fetched rows and main-thread blocking. Backup: export, strict parse, diff, transactional import and rollback/relaunch; time/peak memory/file bytes. LAN: both directions, size/time/throughput/peak memory, idle and stalled peers, cancellation/interruption; physical links separately.
- Background: widget reload counts and freshness after every write/read-state/task action/midnight, reminder scheduling/actions, background work; device energy/thermal/battery over a fixed workload and duration. No simulator extrapolation.
- Correctness gate: compare record IDs/fields/search order, reminders and widget freshness before accepting speedups; do not introduce blind caches, pagination or refresh throttles.
