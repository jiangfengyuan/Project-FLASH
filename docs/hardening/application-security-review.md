# Application/data/input review and residual boundaries

This is evidence from targeted source review and executed gates, not an exhaustive assurance claim. Independent review/acceptance remains with the owner and Claude. The source scan's coverage is bounded and physical-device gaps remain.

| Boundary | Inspected controls / changes | Verification and remaining limits |
| --- | --- | --- |
| Untrusted backup bytes | All production codecs retain50MiB,100k/section, text/date/type/version/unknown-field constraints. Strict/recovery duplicate-key/depth/value-budget scanners run before full object materialization. New negative and deterministic mutation tests cover malformed, duplicate, oversized and framing inputs | Parent regressions and candidate gates in verification.md. Large valid files still consume substantial memory; host100k workload peaks around2.07GB across the whole process. No claim of mobile memory safety under pressure |
| Import/overwrite/cancel | Apple checks cancellation before synchronous transaction; Android owns input/job generations and atomically rechecks overwrite state within Room; reminders serialize after commit. Existing transactional rollback paths preserved | Native Room failure/rollback and separate-process persistence pass; SwiftData native host save/reopen passes. Harmony controller/RDB-fake tests pass; M16 additionally makes overwrite/clear/delete business and read-state writes share an RDB transaction with memory publication only after commit. No physical power-loss claim; cancellation cannot undo an already committed transaction |
| Files/share and path inputs | Apple exclusive0600/no-follow temporary creation, failure cleanup and atomic replacement with private metadata. Android nonexported FileProvider exposes only shared-backups cache and grants selected recipients; generated names. Harmony picker/provider URIs and fixed caller prefixes; shared-download export remains explicitly user initiated | Local POSIX/symlink/short-write/cleanup tests pass where present. Provider/remote-volume ACL behavior and all physical share-sheet recipients not verified. Exported plaintext belongs to the chosen recipient/location; OS sharing does not make it encrypted |
| Deep links/App Intents | iOS AppState recognizes only capture/today/ideas; category maps through enum. CaptureFlashIntent uses QuickCaptureCommit empty/UTF16 bounds, with generic success/error text. No URL field becomes a file path or SQL fragment on these paths. Android launcher only exported activity; Harmony exported launcher has home skill, form extension is separate | Existing iOS deep-link/routing/commit gates pass; malformed/over-limit capture tests retained. No arbitrary file-import URL routing added; accessibility/real Siri/Control Center/widget hardware flows remain unverified |
| Logs/crash diagnostics | Legacy PIN/proof/payload protocol no longer ships. Apple storage-fallback fatal/log messages, read-state/reminder failure logs and Harmony quarantine failure logs now retain static event identifiers instead of interpolating Error/NSError payloads | A synthetic IO exception containing a private-data marker fails the new Harmony test before the fix and passes after it; failure remains diagnosable. This does not establish absence of all OS crash-report metadata. DEBUG-only synthetic seeder diagnostics remain developer-only |
| Widget privacy | Existing Apple snapshots contain date/counts/mood/unread count, not record bodies. Home/lock-screen WidgetKit content is marked privacySensitive; unlocked layout and refresh pipeline unchanged. No new entitlement or protection-class flag | Native builds compile; count/read-state/widget-refresh gates retained. Locked-device redaction and accessibility disclosure depend on OS/user policy and remain physical-device verification. Android has no current widget target; Harmony summary form counts/lock-surface policy need native review |
| Local persistence/cloud policy | Store locations/schema unchanged except separately approved additive Room4→5. App Group still snapshots only. Android allowBackup=false plus cloud/device-transfer exclusions remain. No new persistent session secret or keystore requirement introduced | Native macOS/Android save/reopen tested with fictional isolated stores. iOS protection classes, OEM backup interpretation and Harmony backup/form/real encrypted-RDB behavior not verified. No app cloud sync does not mean an OS device backup excludes app data; Apple/Harmony OS-backup policy remains a documented product decision |
| Build chain | Existing platform dependencies use checked-in versions; no new runtime dependency/SDK. CI actions use immutable SHAs. Gradle wrapper distribution checksum pinned to official8.14.3; checked-in wrapper JAR matches official checksum | Cached build gates do not revalidate already-extracted distributions. Transitive dependency locking/verification and optional mirror trust remain follow-up; no dependency upgrades/obfuscation/signing change made |
| Credentials | Owner explicitly excluded keystore/credential remediation from this branch | No credential copied, generated, printed, rotated or reconfigured here. Separate remediation and approval remain required; this review does not close pre-existing credential findings |

Apple's [WidgetKit guidance](https://developer.apple.com/documentation/widgetkit/creating-a-widget-extension) recommends privacySensitive for sensitive locked-device content. This marker lets native policy redact; it is not a claim that every device configuration hides every count or mood. Do not infer real-device behavior from simulator compilation.
