# 安全 LAN 重建建议 · 2026-10-31

状态：设计交付，不是已实现或已批准上线的协议。当前生产代码仍全部停用旧 LAN，依赖未增加。推荐先评审「临时密钥 + 双端人工短码确认」方向，再单独批准实现；不要直接按本建议拼接密码协议。

## 方案与依赖核查

| 方案 | 优点 | 代价与限制 | 建议 |
| --- | --- | --- | --- |
| SPAKE2 PAKE + 显式双向密钥确认 + AEAD | 用户可输入一次性口令；正确实现能避免旧版离线PIN猜测问题 | 需要四端统一参数/身份/确认与速率限制；RFC不等于库实现已审计。RustCrypto仓库的spake2当前主线标为0.5.0-pre.0，不能直接假定与RFC9382套件/向量一致；Harmony工具链、FFI与RNG未验证 | 保留候选；若优先单端输入体验，再专项评审 |
| 临时密钥 + 承诺/揭示 + SAS人工比较 + 双端确认 + AEAD | 不输入或传递弱口令；可沿用成熟SAS流程与测试参考 | 用户必须在两个设备核对并确认；不能用裸ECDH截断哈希替代承诺流程，无法阻止用户盲点确认 | **首选评审方向**，不是密码组合已经获安全批准 |

截至本次官方资料核查：

- [RustCrypto PAKEs](https://github.com/RustCrypto/PAKEs)提供spake2，MIT/Apache-2.0双许可；[主线Cargo清单](https://github.com/RustCrypto/PAKEs/blob/master/spake2/Cargo.toml)为预发布版本。原生Rust不代表Swift/JNI/ArkTS绑定已有支持，不能声称四端直接可用。规范与确认要求见[RFC9382](https://www.rfc-editor.org/rfc/rfc9382.html)。
- [vodozemac](https://github.com/matrix-org/vodozemac)为Matrix维护的Rust实现，Apache-2.0，README使用0.11.1并列出一次外部审计；包含SAS能力。审计不自动覆盖未来Flash集成或整个Matrix协议。本方向优先评估其SAS API和[Matrix SAS承诺/确认流程](https://spec.matrix.org/v1.16/client-server-api/#short-authentication-string-sas-verification)，不得删减其安全步骤后沿用原审计结论。
- [libsodium](https://github.com/jedisct1/libsodium)为维护中的C库，ISC许可，[官方发布页](https://github.com/jedisct1/libsodium/releases)列1.0.22。[安装文档](https://doc.libsodium.org/installation)提供Apple与Android构建流程；[XChaCha20-Poly1305](https://doc.libsodium.org/secret-key_cryptography/aead/chacha20-poly1305)可作为统一记录层AEAD候选。Harmony NDK/ABI、系统随机源与包体没有在本轮验证，须先完成原型。libsodium的key-exchange API本身不是PAKE，也不提供人工身份确认。

建议原型统一使用一份受审查的SAS核心（优先评估vodozemac）和一份记录层实现（libsodium候选），以窄C ABI暴露给Apple、Android JNI与Harmony N-API。相比四端分别手写协议，可减少语义漂移；代价是引入Rust/C构建链。确切锁定版本、FFI、构建来源哈希、许可证告知、供应链与审计覆盖须作为独立批准项，本轮不下载或链接这些库。若Harmony不能可靠构建，保持该端LAN停用，不回退旧协议。

## 建议交互与安全状态机

1. **主动开启**：用户选择发送或接收才启动短期服务。发现名/图标/IP只作候选选择，不能认证身份；分享扩展和小组件不监听、不参加配对。LAN是快照传输，不是自动同步。
2. **协商**：独立版本标识 `FLASH-LAN/2` 与独立发现类型；拒绝旧 `FLASH-AERO/1`。双方Hello包含32字节随机会话随机数、明确发送/接收角色、支持版本及密码套件。只接受精确允许集合；规范化长度前缀编码，拒绝重复字段、额外字段和角色冲突。
3. **配对**：使用受评审SAS方案的承诺/揭示顺序绑定双方临时公钥和完整Hello transcript。必须在对端信息可被自适应挑选前固定承诺。SAS衍生输入包含协议域、版本、角色、会话ID和有序transcript；最低人工比较目标为至少30比特，界面显示分组数字或同等强度词组。不得把该短码直接当作AEAD密钥。
4. **确认**：两个设备都须显示本次会话短码并由本机用户确认；分别发送密钥确认与本机接受标记，绑定transcript及角色。任一端未确认、确认码不同、确认失败或超时，双方均不能准备/发送备份正文。未认证错误只结束当前有界连接，不能撤销整个服务或伪造成功。MITM/主动猜测上界由评审确定，不能只凭显示30比特就宣称达到30比特认证。
5. **传输**：双端确认后才获取发送快照、严格序列化。每方向独立衍生密钥、nonce前缀与单调计数器；AEAD附加数据绑定会话、方向、版本、记录类型、序号和长度。建议最大明文记录64KiB、总明文50MiB（沿用导入限制），禁止重复/乱序/截断/溢出。最后认证记录包含总字节数及整包摘要，接收方验证完整性后才提供预览。
6. **提交**：接收不自动写库，仍需差异预览、合并/覆盖与过期预览再确认。网络“收齐”与“导入完成”分别显示，未确认导入不得告诉发送方已落库。提醒失败单独报告已导入但提醒恢复失败。

建议默认：开启窗口120秒，连接/单帧等待10秒，人工比较最多60秒，传输绝对上限120秒；单会话仅一个活跃配对、最多3次失败后需本机重新开启。配对重试、断线重试都生成新临时密钥、会话和nonce，不续用旧计数器、不支持断点续传。时限由单调时钟控制，后台/取消/进程退出撤销配对并清除内存密钥及未提交临时文件。系统备份、日志、崩溃附加信息不得保存密钥、PIN、SAS或正文。DoS无法完全消除，不以限速声称网络攻击不存在。

这里给出的是行为与边界；最终transcript字节编码、SAS承诺输入、KDF域、确认MAC及记录格式必须形成独立可审查规格及向量，完成审查后才能实现生产握手。不能以“库已审计”替代Flash组合审查。

## 向量与攻击验收清单

- PAKE候选必须先通过[RFC9382附录A](https://www.rfc-editor.org/rfc/rfc9382.html#appendix-A)全部适用向量；若选用库的曲线/编码不同，明确标注“不兼容该套件”，不能改期望值以通过。
- SAS核心使用选定版本上游已知答案与Matrix承诺/确认参考测试；AEAD使用libsodium官方 `test/default/aead_xchacha20poly1305.c` 与对应 `.exp`。上游向量只是原语门禁，不是Flash互操作向量。
- 下阶段创建四端共享 `lan-v2-vectors.json`，每条包含版本/套件/角色、固定测试随机数和私钥、精确编码Hello/承诺/揭示、transcript摘要、SAS、方向密钥、确认记录、nonce/AAD/密文及预期状态。固定密钥只允许在测试夹具；由参考实现生成并由独立实现核对。当前未实现协议，因此不伪造SAS/密文已知答案。
- 必须拒绝：单方确认、空/小阶/非法公钥、角色反射、版本降级、承诺后换钥、transcript任一字节改动、SAS不匹配、会话/确认重放、假服务名、未认证ERR、错误tag、跨方向密文、nonce复用、重复/跳号记录、头超长、声明大小溢出、50MiB超限、截断末帧及慢滴连接。
- 每个失败点核对零备份正文提前释放、数据库原状、临时文件清理、无成功提示；同时验证取消/超时/前后台切换、通知权限拒绝、过期覆盖预览、失败后新会话重试。四端两两双向共12方向需要文件与网络分层证据，模拟器/替身不替代真机。

## 权限恢复与分期

本轮声明移除不更改数据库或App Group，系统分享仍由系统服务完成。升级到停用版不再声明旧LAN能力；降级到旧二进制会恢复其脆弱代码/声明，绝非安全回滚。未来重加权限需新构建并重新申请适用系统授权，不尝试恢复历史授权状态。

| 平台 | 仅在安全实现启用且验收前恢复 |
| --- | --- |
| iOS | 新发现类型的Bonjour声明及准确的本地网络用途说明；更新对应商店隐私说明，不触碰App Group团队配置 |
| macOS | 实际需要的client/server沙箱entitlement及本地网络/Bonjour声明；随后独立签名、公证与安装验证 |
| Android | INTERNET；只有实际调用需要时才加网络状态/多播/Wi-Fi邻近权限，并按系统版本验证，不能整组恢复旧声明 |
| HarmonyOS | INTERNET及所选发现API实际要求的最小能力；真机准入、证书和API行为单独验证 |

阶段A：批准协议方向、精确依赖与四端构建可行性，完成威胁模型及独立组合审查。阶段B：隔离原型与共享向量、模糊/状态机负例，无生产开关。阶段C：Apple/Android/Harmony原生适配及真机12方向验收，覆盖锁屏、后台、最低系统、取消和大文件。阶段D：批准最小权限恢复、签名产物与分发资料；单独决定何时启用。任一阶段失败继续文件备份，不恢复旧实现。
