# Isolated verification probes

Developer evidence only: use fictional files and NEW disposable directories/output names. These tools never open the default Apple store/App Group or an app's daily database. They add no app target, SDK or third-party runtime dependency. Recorded commands are serial; stop emulators/simulators before building/profiling. None of these probes establishes installed-app UI or physical-device acceptance.

- `swift build -c release` here, with `DEVELOPER_DIR=/Applications/Xcode-beta.app/Contents/Developer`. `FlashBackupProbe INPUT.json NEW-output.json` executes the actual FlashCore parser/exporter/parser and compares every model and incoming schema2 metadata field. `FlashPersistenceProbe write NEW-directory INPUT.json`, then a separate `read directory INPUT.json`, verifies the production SwiftData/repository/read-state after process exit with the existing schema/plan.
- `harmony-cross-export.cjs INPUT.json NEW-output.json` executes actual ArkTS parser/exporter through the repository Node loader, compares model equality and incoming metadata. Set `FLASH_TYPESCRIPT_PATH` to the existing installed TypeScript module if necessary. RDB/i18n/platform substitutes are explicit; native RDB/form behavior is not established.
- `AndroidBackupProbe.java` compiles with JDK21 against `android/app/build/tmp/kotlin-classes/release`, existing `org.json:json:20231013` and `kotlin-stdlib:2.2.0` test runtime jars. Put compiled helper classes in a new scratch directory and use the same classpath at runtime. Arguments: schema1 seed, actual peer export, NEW self-export. Reports distinguish native Java rules from production-codec acceptance. This is host JVM, not Android ART/Room. Run Gradle tests/build first rather than compiling modified production sources separately.
- Native Android `Schema2ProcessProbeTest`: after building app/test Debug APKs with the README toolchain, install only into a dedicated disposable emulator. Invoke `am instrument -w -r -e class com.flash.app.data.Schema2ProcessProbeTest -e schema2ProbePhase write -e schema2ProbeInput apple|harmony com.flash.app.native.test/androidx.test.runner.AndroidJUnitRunner`. Force-stop `com.flash.app.native`; invoke `read` with the same input. The bounded input option selects recorded assets, and each has its own fictional database. Retrieve `files/hardening-schema2-<input>-android-export.json` via `run-as` only in this container. The ordinary suite intentionally skips this two-invocation probe.
- `backup-compatibility-probe.cjs REPO [NEW-self-export [actual-peer-export]]` records a historical/current Harmony diagnostic, including source hash. Keep before/after outputs separately; do not overwrite baseline evidence. `lan-baseline-repro.cjs` explicitly exercises the historical archived sender, never a production secure replacement.

Inputs/provenance and tiered results: `docs/hardening/evidence/compatibility/manifest.json`, `docs/hardening/compatibility-blockers.md`, Android test assets. Original unchanged exporter bytes and baseline rejections are retained. A successful parser alone does not prove transaction, file-picker, reminder, widget or full app relaunch behavior. Output files are fictional artifacts; do not feed personal exports into these evidence tools.
